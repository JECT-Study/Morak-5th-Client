## 파트별 사용법

### FE · BE

레포에서 이슈 템플릿으로 이슈를 만들면 라벨과 보드 등록이 자동으로 됩니다.

1. 레포 → Issues → New issue → 템플릿 선택 (기능 개발 / 버그 제보 / 작업)
2. 이슈 오른쪽 **Fields**에서 Start date · Target date 입력
3. 작업을 시작하면 보드에서 **In Progress**로 이동
4. PR 본문에 `close #이슈번호` 작성 → 이슈가 자동으로 **In Review**
5. PR 머지 → 이슈가 자동으로 닫히고 **Done**

### PD · PM

세부 작업은 지금처럼 노션·피그마에서 관리하고, 보드에는 **개발 일정에 영향을 주는 작업만** 올립니다. 이미 끝난 기획·디자인은 올리지 않아도 됩니다.

1. 보드 하단 **+** → Create new issue → Morak-5th-Client → **디자인·기획** 템플릿
2. 기능(F01~F05) 선택, 피그마·노션 링크 입력
3. 오른쪽 Labels에서 PD는 `🎨design`, PM은 `📋planning` 선택
4. 만든 뒤 오른쪽 **Fields**에서 Start date · Target date 입력
5. 끝나면 보드에서 **Done**으로 이동

일정이 바뀌면 Target date만 고쳐주세요. 개발 일정이 이 날짜를 기준으로 잡힙니다.

## 상태 흐름

| 상태        | 뜻                           | 바뀌는 방법                     |
| ----------- | ---------------------------- | ------------------------------- |
| Todo        | 작업 전                      | 이슈를 만들면 자동              |
| In Progress | 작업 중                      | 직접 이동                       |
| In Review   | PR 리뷰, 디자인·기획 검토 중 | PR에 `close #번호`를 쓰면 자동  |
| Done        | 완료                         | PR 머지 또는 이슈를 닫으면 자동 |
| Canceled    | 진행하지 않기로 함           | 직접 이동                       |

## 라벨

| 라벨         | 파트 | 붙는 방법              |
| ------------ | ---- | ---------------------- |
| `👩🏻‍💻frontend` | FE   | Client 템플릿에서 자동 |
| `👨🏻‍💻backend`  | BE   | Server 템플릿에서 자동 |
| `🎨design`   | PD   | 직접 선택              |
| `📋planning` | PM   | 직접 선택              |

작업 종류 라벨(`✨feature`, `🐛bug`, `⚙️chore` 등)은 템플릿에 따라 자동으로 붙습니다.

| 필드                     | 설명                                                           |
| ------------------------ | -------------------------------------------------------------- |
| Start date · Target date | 시작일과 완료 예정일. 작업 일정 보기에 표시                    |
| 스프린트                 | 위 전체 일정 표의 스프린트                                     |
| 우선순위                 | P0 지금 바로 / P1 이번 스프린트 안에 / P2 여유 있을 때         |
| 작업 종류                | Feature, Bug, Design, Planning, Refactor, Chore, Docs, Meeting |

## 지켜주세요

- 모든 PR은 이슈와 연결합니다 (`close #이슈번호`).
- 날짜가 바뀌면 바로 Target date를 고칩니다. 날짜가 실제와 다르면 일정표를 믿을 수 없게 됩니다.
- 이슈 하나는 1~3일 안에 끝낼 크기로 나눕니다. 더 크면 쪼개 주세요.

## BE 요청 사항

- Server 레포 Settings → Projects(또는 Projects 탭)에서 **Ject-5th-7** 보드 연결
- Server 레포 `.github/ISSUE_TEMPLATE/issue.md` 상단 수정

```yaml
labels: ["👨🏻‍💻backend"]
projects: ["JECT-Study/29"]
type: Feature
```

`type: Feature`가 있어야 이슈에 Start date · Target date 칸이 생깁니다. 라벨 이름은 이모지까지 같아야 하니 Labels 페이지에서 복사해 붙여 넣어 주세요.
